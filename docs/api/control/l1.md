# l1

L1 adaptive controller with state predictor, projection-based adaptation, and
low-pass filtered control output. In the L1 architecture the low-pass filter, not
the adaptation gain, sets the bandwidth of the control signal; the theory's
transient and robustness bounds rest on a condition on that filter which ctrlpp
does not check (see [Limitations](#limitations)). Supports SISO (NX=NU=1) and
square MIMO (NX=NU) configurations with matrix adaptation gains. The filter stage
reuses ctrlpp's biquad infrastructure through vector_biquad.

## Header and Alias

| Form | Header |
|------|--------|
| `ctrlpp::l1_controller<Scalar, NX, NU, Filter>` | `#include <ctrlpp/control/l1.h>` |

## Template Parameters

| Parameter | Constraint | Description |
|-----------|------------|-------------|
| `Scalar` | `ctrlpp_floating_scalar` | Floating-point type (e.g. `double`, `float`) |
| `NX` | `std::size_t`, default `1` | State dimension |
| `NU` | `std::size_t`, default `1` | Input dimension |
| `Filter` | `vector_discrete_filter<Filter, Vector<Scalar, NU>>`, default `vector_biquad<Scalar, NU>` | Low-pass filter type for control output |

`NX` must equal `NU` (a square predictor), enforced by a `static_assert`. The
reference feedforward gain is formed by inverting the predictor DC gain, which
requires a square, invertible model. The general non-square feedforward gain
`k_g = -(C (I - A_m)^{-1} B)^{-1}` is not yet implemented.

## Config: l1_config

```cpp
template <ctrlpp_floating_scalar Scalar, std::size_t NX, std::size_t NU>
struct l1_config;
```

Header: `#include <ctrlpp/control/l1_config.h>`

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `predictor_model` | `discrete_state_space<Scalar, NX, NU, NX>` | zero | Desired closed-loop dynamics (A_m, B_m, C_m, D_m) |
| `gamma` | `Matrix<Scalar, NU, NU>` | Identity | Adaptation gain matrix (meant to be SPD; not checked) |
| `theta_min` | `Vector<Scalar, NU>` | `-infinity` | Elementwise lower bound for projection |
| `theta_max` | `Vector<Scalar, NU>` | `+infinity` | Elementwise upper bound for projection |
| `x_hat_0` | `Vector<Scalar, NX>` | zero | Initial predictor state |
| `sigma_hat_0` | `Vector<Scalar, NU>` | zero | Initial uncertainty estimate |

The `predictor_model` uses the desired closed-loop dynamics (A_m), not the unknown
plant dynamics. `gamma` is the adaptation gain. The continuous-time L1 theory lets it
be arbitrarily large because robustness comes from the filter bandwidth rather than
from the gain, but the discrete update `l1_controller` runs bounds it from above
(see [Limitations](#limitations)); the examples below use 150 and 100. `theta_min`
and `theta_max` define elementwise projection bounds that keep the uncertainty
estimate bounded. They default to an unbounded range (`-infinity` to `+infinity`),
so a default-constructed config adapts freely; set finite bounds to enable the
elementwise projection.

## Construction

`create` is the only construction path: it computes the feedforward gain from the
predictor model, refusing a model that does not yield a finite one, and returns
`ctrlpp::expected<l1_controller, l1_error>` instead of throwing. It does not check
`gamma`, the projection bounds or the initial values; a non-finite initial value is
reported by the first `evaluate`. There is no non-fallible constructor, so a
rejected configuration is a value the caller has to inspect and never a
controller that quietly stands in for one. Two overloads
mirror the two ways of providing the low-pass filter that decouples adaptation
from control:

### create (filter design)

```cpp
static ctrlpp::expected<l1_controller, l1_error> create(const config_type& cfg, Scalar cutoff_hz, Scalar sample_hz);
```

Builds a 2nd-order Butterworth low-pass via `vector_biquad::low_pass()`, replicated
across NU channels. `cutoff_hz` must lie in the open interval `(0, sample_hz / 2)`
(Nyquist limit) and above the coefficient-resolution floor of the scalar type (see
[biquad](../dsp/biquad.md#coefficient-resolution-floor)); a rejected filter design yields
`l1_error::invalid_filter_config`.

### create (direct filter)

```cpp
static ctrlpp::expected<l1_controller, l1_error> create(const config_type& cfg, Filter filter);
```

Accepts any type satisfying `vector_discrete_filter`. Use for higher-order filters
or custom filter types.

### Validation: l1_error

Header: `#include <ctrlpp/control/l1_config.h>`

```cpp
enum class l1_error {
    singular_predictor,
    singular_dc_gain,
    non_finite_gain,
    invalid_filter_config,
};
```

| Enumerator | Rejected configuration |
|------------|------------------------|
| `singular_predictor` | `(I - A_m)` is singular (predictor has a unit eigenvalue) |
| `singular_dc_gain` | The DC gain `(I - A_m)^{-1} * B` is singular or non-finite (near-zero steady-state gain) |
| `non_finite_gain` | The feedforward gain `K_r` is non-finite (ill-conditioned predictor model) |
| `invalid_filter_config` | The filter design was rejected by the dsp factory (see `ctrlpp::dsp_error`): non-finite parameter, non-positive sample rate, cutoff outside `(0, sample_hz / 2)`, or cutoff below the coefficient-resolution floor of the scalar type |

```cpp
auto ctrl = ctrlpp::l1_controller<double>::create(cfg, 5.0, 100.0);
if (!ctrl.has_value()) {
    // inspect ctrl.error() and reject the configuration
}
auto u = ctrl->evaluate(x, r);
```

### Supplying the filter directly

```cpp
// 4th-order Butterworth at 5 Hz, 100 Hz sample rate. Both factories are
// fallible; ctrl is inspected as in the example above.
using filter_t = ctrlpp::vector_cascaded_biquad<double, 1, 2>;

auto filter = ctrlpp::make_vector_butterworth<4, 1>(5.0, 100.0);
if(!filter)
    return filter.error();
auto ctrl = ctrlpp::l1_controller<double, 1, 1, filter_t>::create(cfg, *std::move(filter));
```

```cpp
// 4th-order Chebyshev Type I with 1 dB passband ripple
using filter_t = ctrlpp::vector_cascaded_biquad<double, 1, 2>;

auto filter = ctrlpp::make_vector_chebyshev1<4, 1>(5.0, 100.0, 1.0);
if(!filter)
    return filter.error();
auto ctrl = ctrlpp::l1_controller<double, 1, 1, filter_t>::create(cfg, *std::move(filter));
```

## Class Methods

### evaluate

```cpp
expected<input_type, l1_step_error> evaluate(const state_type& x, const input_type& r);
```

Computes the filtered control output for the current time step. Internally
executes the full L1 pipeline: state predictor update, prediction error
computation, projection-based adaptation, feedforward plus cancellation, and
low-pass filtering. Call once per time step. On success the result carries the
filtered control vector.

The cycle is classified before any member is written, so a rejected cycle leaves
the predictor state, the prediction error, the uncertainty estimate and the
previous command bitwise unchanged, and a following valid cycle produces exactly
what it would have produced had the rejected one never been attempted. As with
any adaptive law, the uncertainty estimate is only accumulated into and never
re-derived, so one admitted non-finite sample would be permanent.

**A refused cycle produced no command.** The actuator will be driven by something
regardless, and the caller must choose what: hold the command the last successful
cycle returned, drive a configured safe value, or fail over. The controller does
not choose, because the right answer is a property of the plant.

| Enumerator | Cause | Where the caller repairs it |
|---|---|---|
| `non_finite_predictor_state` | The predictor's carried state is already non-finite -- the predicted state or the previous filtered command, both of which feed the predictor propagation. A committed cycle never leaves them non-finite, so this traces to a non-finite `x_hat_0`. | The initial predictor state. Reported ahead of the adaptation because it is upstream of it. |
| `non_finite_adaptation` | The carried uncertainty estimate is already non-finite. A committed cycle never leaves it non-finite, so this traces to a non-finite `sigma_hat_0`. | The initial estimate. |
| `non_finite_state` | The supplied plant state has a non-finite component. | The sensor or estimator. |
| `non_finite_reference` | The supplied reference command has a non-finite component. | The command generator. |
| `non_finite_result` | The cycle's own arithmetic produced a non-finite value: the propagated predictor state, the prediction error, the projected estimate, the unfiltered command or the filtered command. Nothing is committed. A `NaN` adaptation update, and an infinite one against an infinite projection bound, end here. | The adaptation gain, the predictor model or the magnitude of the arguments. |

#### What the projection does with a non-finite estimate

The projection is the elementwise `cwiseMax(theta_min).cwiseMin(theta_max)`.
Eigen reduces both to `numext::maxi`/`numext::mini`, written `x < y ? y : x` and
`y < x ? y : x` (Eigen 3.4.1, `Eigen/src/Core/MathFunctions.h:1282` and `:1249`,
reached through `scalar_max_op`/`scalar_min_op` at
`Eigen/src/Core/functors/BinaryFunctors.h:143`). Both return the **left** operand
when the comparison is false, and every comparison against a `NaN` is false. Two
consequences follow, and they differ:

- A `NaN` estimate is returned unchanged by both halves, so the projection does
  **not** sanitize it. The projected estimate is tested before anything is
  committed, so the cycle is refused with `non_finite_result`.
- An infinite estimate **is** replaced, by `theta_max` or `theta_min` -- but only
  when that bound is itself finite. The default configuration leaves the bounds
  at -/+ infinity, and against an infinite bound the comparison is false again,
  the infinity survives, and the cycle is refused with `non_finite_result`.

The second case is the dangerous one, and it is reachable with entirely finite
arguments: a large adaptation gain against a large prediction error overflows to
an infinity, the projection pins it to a legitimate bound, and the controller
then emits a finite, in-range command computed from an estimate that carries no
information. Nothing downstream can detect that. The raw update is therefore
tested for finiteness **before** the clamp, and `health()` latches
`projection_clamped_non_finite` when it fails. The cycle still succeeds, because
it did produce the command the algorithm prescribes; the status is what says the
command should not be trusted.

### health

```cpp
l1_health health() const;
```

Reports whether the controller is carrying damage: an uncertainty estimate the
projection silently substituted a bound for (`projection_clamped_non_finite`, set
by a cycle that succeeded), or non-finite carried state (`non_finite_carried_state`,
set by the cycle that is refused with `non_finite_predictor_state` or
`non_finite_adaptation`). Latches until `reset` and never downgrades: the
enumeration is a severity ladder (`ok` < `projection_clamped_non_finite` <
`non_finite_carried_state`), so a lesser fault cannot mask a greater one recorded
earlier.

A cycle refused on its arguments (`non_finite_state`, `non_finite_reference`) or on
its own arithmetic (`non_finite_result`) does not set it.

### x_hat

```cpp
const state_type& x_hat() const;
```

Returns a const reference to the current predicted state vector.

### sigma_hat

```cpp
const input_type& sigma_hat() const;
```

Returns a const reference to the current matched uncertainty estimate vector.

### tracking_error

```cpp
const state_type& tracking_error() const;
```

Returns a const reference to the prediction error (x_hat - x) of the last
committed cycle.

### theta

```cpp
const input_type& theta() const;
```

Returns a const reference to the adapted parameter vector. Alias for `sigma_hat()`,
named for consistency with MRAC's `theta_x` / `theta_r`.

### reset

```cpp
void reset();
```

Resets predictor state, uncertainty estimate, prediction error, control history,
filter state and `health()` to their initial values: `x_hat_0` and `sigma_hat_0`
from the config, zero, and `l1_health::ok`.

## Usage Examples

### SISO: First-Order Plant Tracking

```cpp
// Usage: gnuplot -p -e "set datafile separator ','; set key autotitle columnheader;
//   plot '<./ctrlpp_l1_01_tracking' using 1:2 with lines title 'reference',
//        '' using 1:3 with lines title 'plant',
//        '' using 1:4 with lines title 'predictor'"

#include "ctrlpp/control/l1.h"

#include <iomanip>
#include <iostream>

int main()
{
    using controller = ctrlpp::l1_controller<double>;
    using config = controller::config_type;

    ctrlpp::discrete_state_space<double, 1, 1, 1> pred_model{};
    pred_model.A(0, 0) = 0.9;
    pred_model.B(0, 0) = 0.1;
    pred_model.C(0, 0) = 1.0;
    pred_model.D(0, 0) = 0.0;

    config cfg{};
    cfg.predictor_model = pred_model;
    cfg.gamma(0, 0) = 150.0;
    cfg.theta_min[0] = -10.0;
    cfg.theta_max[0] = 10.0;

    auto created = controller::create(cfg, 2.0, 100.0);
    if (!created.has_value()) return 1;
    auto& ctrl = *created;

    constexpr double a_p = 0.8, b_p = 0.5;
    double x_plant = 0.0;

    ctrlpp::Vector<double, 1> r;
    r[0] = 1.0;

    for (int k = 0; k < 500; ++k) {
        ctrlpp::Vector<double, 1> x;
        x[0] = x_plant;
        // A refused cycle produced no command AND left the adaptive
        // parameters untouched; the caller decides what the actuator does.
        auto step = ctrl.evaluate(x, r);
        if (!step.has_value()) return 1;
        const auto& u = *step;

        std::cout << std::fixed << std::setprecision(6)
                  << k << "," << 1.0 << "," << x_plant << ","
                  << ctrl.x_hat()[0] << "," << u[0] << ","
                  << ctrl.sigma_hat()[0] << "\n";

        x_plant = a_p * x_plant + b_p * u[0];
    }
}
```

### MIMO: Two-Channel Tracking

```cpp
#include "ctrlpp/control/l1.h"

#include <iomanip>
#include <iostream>

int main()
{
    constexpr std::size_t NX = 2;
    constexpr std::size_t NU = 2;

    using controller = ctrlpp::l1_controller<double, NX, NU>;
    using config = controller::config_type;

    ctrlpp::discrete_state_space<double, NX, NU, NX> pred_model{};
    pred_model.A << 0.9, 0.0,
                    0.0, 0.85;
    pred_model.B << 0.1, 0.0,
                    0.0, 0.15;
    pred_model.C = ctrlpp::Matrix<double, NX, NX>::Identity();
    pred_model.D = ctrlpp::Matrix<double, NX, NU>::Zero();

    config cfg{};
    cfg.predictor_model = pred_model;
    cfg.gamma = 100.0 * ctrlpp::Matrix<double, NU, NU>::Identity();
    cfg.theta_min = -10.0 * ctrlpp::Vector<double, NU>::Ones();
    cfg.theta_max = 10.0 * ctrlpp::Vector<double, NU>::Ones();

    auto created = controller::create(cfg, 2.0, 100.0);
    if (!created.has_value()) return 1;
    auto& ctrl = *created;

    ctrlpp::Matrix<double, NX, NX> A_p;
    A_p << 0.8, 0.1,
           0.0, 0.7;
    ctrlpp::Matrix<double, NX, NU> B_p;
    B_p << 0.5, 0.0,
           0.0, 0.4;

    ctrlpp::Vector<double, NX> x_plant = ctrlpp::Vector<double, NX>::Zero();
    ctrlpp::Vector<double, NU> r;
    r << 1.0, 0.5;

    for (int k = 0; k < 500; ++k) {
        // A refused cycle produced no command AND left the adaptive
        // parameters untouched; the caller decides what the actuator does.
        auto step = ctrl.evaluate(x_plant, r);
        if (!step.has_value()) return 1;
        const auto& u = *step;

        std::cout << std::fixed << std::setprecision(6)
                  << k << ","
                  << r[0] << "," << x_plant[0] << "," << ctrl.x_hat()[0] << ","
                  << r[1] << "," << x_plant[1] << "," << ctrl.x_hat()[1] << ","
                  << u[0] << "," << u[1] << "\n";

        x_plant = A_p * x_plant + B_p * u;
    }
}
```

## Algorithm

The L1 `evaluate()` pipeline executes these steps each time step:

1. **State predictor:** x_hat = A_m * x_hat_prev + B * (u_prev + sigma_hat)
2. **Prediction error:** x_tilde = x_hat - x
3. **Adaptation:** sigma_hat -= Gamma * B^T * x_tilde, clamped to [theta_min, theta_max]
4. **Control:** u_raw = K_r * r - sigma_hat
5. **Filter:** u = C(z) * u_raw
6. **Return** u, which is also the next cycle's u_prev

K_r (feedforward gain) is computed internally from the predictor model DC gain:
K_r = ((I - A_m)^{-1} * B)^{-1}. `create` tests that both inversions are
invertible to Eigen's default full-pivoting LU rank threshold and that the results
are finite, and returns the matching `l1_error` if not (see Validation above).

Reference: Hovakimyan & Cao, "L1 Adaptive Control Theory", 2010, Ch. 2.

## Design Notes

- The low-pass filter is the robustification mechanism of the L1 architecture;
  `l1_controller` has no dead-zone or sigma-modification policy
- The continuous-time L1 theory takes large adaptation gains and lets the filter
  set the closed-loop bandwidth; the discrete update caps the gain, and
  [Limitations](#limitations) states the cap and what this implementation does
  not check
- `NX != NU` does not compile (see Template Parameters)

## Limitations

### The adaptation law fixes the Lyapunov weight to the identity

The update is `sigma_hat -= gamma * B^T * x_tilde`: the gradient `B^T P x_tilde`
of the L1 adaptation law with the Lyapunov weight `P` fixed to the identity, where
`B` is the predictor model's input matrix. For the discrete-time predictor
`l1_controller` takes, `P = I` is a valid Lyapunov weight exactly when
`I - A_m^T A_m` is positive definite, that is when the spectral norm of the
predictor's `A_m` is below one. A stable `A_m` outside that set needs a different
`P`, which `l1_config` does not expose, and ctrlpp does not check the condition.
The update also carries no `dt` factor, so `gamma` absorbs the sample time.

### The adaptation gain has a ceiling

Unlike the continuous-time law, the discrete update does not tolerate an
arbitrarily large `gamma`. For a diagonal predictor and an uncertainty held
constant, channel `i` of the prediction error and the estimate error evolve as a
second-order loop with characteristic polynomial
`z^2 - (1 + a_i - gamma_i b_i^2) z + a_i`, where `a_i` and `b_i` are the diagonal
entries of `A_m` and `B`. The Jury test makes it stable exactly when
`0 < gamma_i b_i^2 < 2 (1 + a_i)`. Above that ceiling the estimate diverges and
the projection holds it at its bounds. For the SISO example (`a = 0.9`,
`b = 0.1`) the ceiling is `gamma = 380`; for the second MIMO channel
(`a = 0.85`, `b = 0.15`) it is about 164. ctrlpp does not check it.

### The filter condition of the L1 theory is not checked

The L1 theory's transient and robustness bounds hold only when the low-pass filter
and the uncertainty satisfy a stability condition. `l1_controller` has no model of
the uncertainty and does not test the condition, so the bounds are not guaranteed
by construction. In the usage examples above it shows as a floor on `gamma` that
rises with the filter cutoff toward the ceiling above. With the SISO example's
plant and the ceiling of 380, a 2 Hz filter needs `gamma` of about 30 or more, a
5 Hz filter about 190 and a 10 Hz filter about 360. Below the floor the estimate
alternates between its projection bounds and the plant does not track; only gains
of about 1 or less, too slow to be useful, escape this at some cutoffs. The
examples' values were chosen inside the measured window; they are not derived
from the condition.
